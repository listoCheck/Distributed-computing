# Лабораторная №2: банковская система

Реализация на C99: родитель управляет переводами между дочерними процессами.
Для каждой упорядоченной пары процессов создаётся отдельный pipe, оба конца
переводятся в O_NONBLOCK. Потоков, разделяемой памяти, select/poll нет.

## Сборка и запуск

Нужны Linux, clang и библиотека преподавателя libruntime.so в этом каталоге.
Библиотека не входит в Git и архив для бота.

```sh
make
LD_LIBRARY_PATH=. LD_PRELOAD=./libruntime.so ./pa2 -p 3 10 20 30
```

Поддерживается команда бота:

```sh
clang -g -Wall -pedantic -std=c99 *.c -L. -lruntime -o pa2
```

Параметр -p задаёт число дочерних процессов (до 10), далее идут их начальные
балансы от 1 до 99. Помимо обычных запусков с несколькими счетами поддержан
граничный случай с одним дочерним процессом.

## Протокол

Дети рассылают STARTED и ждут STARTED только от других детей.
Родитель дожидается всех детей и вызывает bank_robbery(). Файл
bank_robbery.c содержит небольшой сценарий, который бот заменяет своим.

Каждый transfer() отправляет поручение источнику и ждёт ACK от получателя.
Источник списывает сумму, пересылает поручение получателю. Получатель
зачисляет сумму и подтверждает перевод родителю.

После bank_robbery() родитель рассылает STOP. Дети отправляют DONE,
сохраняют ранние DONE и продолжают принимать переводы до получения
DONE от всех остальных детей. Затем отправляют родителю BALANCE_HISTORY.
Родитель собирает истории по индексу ID-1, дополняет их до общей длины
и вызывает библиотечную print_history().

Все отметки берутся из get_physical_time(). Промежутки между изменениями
баланса заполняются предыдущим состоянием; s_time соответствует индексу,
s_balance_pending_in всегда нулевой, как требует PA2. В каждый момент
промежуточная общая сумма может отличаться из-за денег в пути.

Формат s_history_len имеет тип uint8_t и вмещает 255 состояний:
t=0..254. Если время нельзя представить в этом формате, программа
возвращает ошибку вместо переполнения длины.

STARTED, DONE и переводы выводятся в терминал и events.log.
В pipes.log записана топология каналов. IPC сохраняет частичные кадры
по каждому отправителю и обрабатывает EINTR, EAGAIN и EOF.

## Проверки

В репозитории:

```sh
make test
make package
```

Тесты проверяют короткие чтения, максимальные кадры и заполнение pipe,
историю до границы длины, ранний DONE и перевод после STOP,
30 банковских сценариев с 1–10 счетами, пустой и кольцевой сценарии,
каждую ячейку истории по событиям, сохранение итоговой суммы и 9
некорректных наборов аргументов. У успешных запусков код 0 и пустой stderr.
Набор также собирает и запускает содержимое итогового архива отдельно.

Стартовые ipc.h, banking.h, common.h, pa2345.h восстановлены из копии
комплекта курса: репозиторий tynrol/ITMO_DistributedSystems, коммит
be37edfc59d57b5d7ac987d9f0fa04528355d2ab, каталог pa2.
Это предоставляемые интерфейсы, а не студенческая реализация.
